## WebUI -> TUI

Using the official WebUI in the existing `camo` `default` profile, a new
Session was opened and the WebUI submitted `DSH_TUI_WEBUI_A`. Public
`session.list` and `session.history` identified the Session above. The clean
installed TUI resumed it with the exact public client:

```text
node <clean-install>/lib/cli.js \
  --endpoint http://127.0.0.1:3080 \
  --resume session-8a1aa31c-773b-4307-87ff-14f6973a19de \
  --cwd /Volumes/extension/code/dsh
```

The TUI hydrated and rendered `DSH_TUI_WEBUI_A`, then the WebUI submitted
`DSH_TUI_WEBUI_B` while the TUI process was still connected. The TUI PTY
observed the new user event, entered `mode=streaming`, then projected the
authoritative provider error:

```text
TUI_HISTORY_A
TUI_READY_FOR_WEBUI_B
DSH_TUI_WEBUI_B
TUI_SAW_WEBUI_B
Session ... [error] host agent error: 429:
{"type":"GoUsageLimitError","message":"Weekly usage limit reached. Resets in 4 days..."}
```

## TUI -> WebUI

The same clean-installed TUI submitted `DSH_TUI_TUI_C` to the same Session.
The official WebUI then displayed the message and its provider error. A fresh
public `session.history` read recorded all three prompts and the three terminal
turn errors:

```json
{
  "prompts": [
    {"seq": 3, "text": "DSH_TUI_WEBUI_A"},
    {"seq": 19, "text": "DSH_TUI_WEBUI_B"},
    {"seq": 28, "text": "DSH_TUI_TUI_C"}
  ],
  "turn_error_seqs": [18, 27, 36],
  "provider": "opencode-go-pool",
  "model": "deepseek-v4-flash"
}
```

The WebUI readable surface showed `DSH_TUI_TUI_C` and the same
`GoUsageLimitError` with weekly reset information. No provider or model
substitution was attempted.

## Error-state PTY restoration

After the TUI received the authoritative 429 for `DSH_TUI_TUI_C`, it rendered
`mode=error`. Sending Ctrl+C in that non-running error state restored the
alternate screen and cursor and returned the actual child status:

```text
TUI_C_ERROR_STATE
TUI_EXITING_CTRLC
TUI_EOF
TUI_WAIT_RESULT=1733 exp6 0 0
TUI_CHILD_EXIT=0
```

## Boundary

The live test proves same-Session history, bidirectional user-event delivery,
streaming/error state propagation, quota error convergence and terminal
restoration. The locked provider returned `GoUsageLimitError` before any
assistant token was produced, so successful assistant-token streaming remains
unverified and is not claimed as closed.
