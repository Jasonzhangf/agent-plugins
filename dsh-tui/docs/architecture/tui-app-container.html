First viewport before first frame

  1. app-shell installs the app-event subscriber and terminal input handler.
  2. terminal-lifecycle enters without mounting and observes real columns and rows.
  3. terminal-lifecycle publishes terminal.resize.
  4. app-event-bus validates, freezes, and synchronously dispatches the exact pair.
  5. app-shell stores that same reference and admits the first compose.
  6. app-container builds; terminal-ui realizes; lifecycle mounts once.

No width-only state, 80 × 24 default, direct validator/store bypass, partial pair, or pre-viewport compose is permitted. Later resize follows the same path.

Frame failure cutover

The node sequence remains CompositionFailure → TerminalFailure → StartupOutcome → ProcessExit. Phase 2 atomically rebinds only the first edge from lifecycle renderWithCompose to an app-shell router that preserves the original cause, calls public TuiTerminalLifecycle.fail, and returns before realization or mount.

Generic realization failure is a separate terminal-ui-owned typed source: PrimitiveFailure → terminal_primitive_realization_failure_chain → TerminalFailure. App-shell preserves its cause and calls the same public fail face before mount. It never enters app_composition_failure_chain; both sources share only the inherited startup and process-exit tail.
